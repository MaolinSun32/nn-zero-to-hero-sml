# Lecture 3: Building makemore Part 2 — MLP 字符级语言模型
#flashcards/nn-zero-to-hero


MLP 语言模型中的 `block_size` 是什么？为什么需要它？
?
`block_size` 是模型的上下文窗口大小，即用前几个字符来预测下一个字符。
bigram 只看 1 个字符，block_size=3 则看前 3 个字符，能捕捉更长的模式（如 "emm" → "a"）
<!--SR:!2026-04-14,8,250-->


用 "emma" 举例，block_size=3 时滑动窗口如何生成训练样本？
?
初始 context 为 `...`，逐步滑动：
`...` → `e`，`..e` → `m`，`.em` → `m`，`emm` → `a`，`mma` → `.`
每步取最近 3 个字符作为输入 X，下一个字符作为标签 Y
<!--SR:!2026-04-15,9,250-->


Embedding 矩阵 C 的形状 `(27, 2)` 中，每个维度代表什么？
?
- 27 = 字符表大小（26 字母 + 1 个特殊符 `.`）
- 2 = 每个字符的嵌入维度（可学习的特征向量长度）
- 每一行是一个字符的"身份证"，训练中自动学出字符间的相似关系
<!--SR:!2026-04-14,8,250-->


`C[X]` 是怎么把整数索引变成嵌入向量的？输入输出形状是什么？
?
PyTorch 的整数索引自动做 table lookup：X 中的每个整数 i 取出 C 的第 i 行。
输入 X 形状 `(N, 3)`，C 形状 `(27, 2)` → 输出 `(N, 3, 2)`
即每个样本的 3 个字符各得到一个 2 维嵌入向量
<!--SR:!2026-04-13,7,250-->


`F.one_hot(x, 27) @ C` 等价于 `C[x]`，为什么？这说明了什么？
?
one_hot 把索引 x 变成只有第 x 位为 1 的向量，乘以 C 就是取出 C 的第 x 行。
说明 embedding lookup 本质上是矩阵乘法的高效实现——跳过了乘零的运算
<!--SR:!2026-04-15,9,250-->


MLP 隐藏层的前向传播公式是什么？每一步做了什么？
?
`h = tanh(emb.view(-1, 6) @ W1 + b1)`
1. `emb.view(-1, 6)`：把 (N,3,2) 展平成 (N,6)，拼接 3 个嵌入
2. `@ W1 + b1`：线性变换，将 6 维输入映射到 100 维隐藏层
3. `tanh`：非线性激活，把值压缩到 [-1, 1]
<!--SR:!2026-04-14,8,250-->


为什么隐藏层需要 tanh 等非线性激活函数？
?
没有非线性，多层线性变换等价于一层（矩阵乘法的组合还是线性的）。
tanh 引入非线性后，网络才能学习复杂的输入→输出映射关系
<!--SR:!2026-04-13,7,250-->


`emb.view(-1, 6)` 做了什么？为什么用 `-1`？
?
将 (N, 3, 2) reshape 成 (N, 6)，把 3 个字符的嵌入拼接成一个长向量。
`-1` 让 PyTorch 自动推断该维度大小（= N），不用手动写 batch size
<!--SR:!2026-04-15,9,250-->


PyTorch 的 `view()` 和数据拷贝是什么关系？
?
`view()` 只改变 tensor 的形状元数据（stride/shape），不拷贝底层数据。
原 tensor 和 view 后的 tensor 共享同一块 `storage()`（底层一维内存）。
所以 view 是零开销操作
<!--SR:!2026-04-14,8,250-->


将 (N,3,2) 嵌入展平为 (N,6) 有哪三种等价写法？哪种最高效？
?
1. `emb.view(-1, 6)` — 最高效，零拷贝 reshape
2. `torch.cat(torch.unbind(emb, 1), 1)` — unbind 按 dim=1 拆开再 cat 拼接
3. `torch.cat([emb[:,0,:], emb[:,1,:], emb[:,2,:]], 1)` — 手动切片拼接
方法 1 最佳，2 和 3 都会创建新 tensor
<!--SR:!2026-04-13,7,250-->


手动实现 softmax + 交叉熵的三步是什么？
?
```python
counts = logits.exp()           # 1. 指数化
probs = counts / counts.sum(1, keepdim=True)  # 2. 归一化为概率
loss = -probs[range(N), Y].log().mean()        # 3. 取正确类的 -log 概率
```
`F.cross_entropy(logits, Y)` 一步完成以上三步，且数值更稳定
<!--SR:!2026-04-15,9,250-->


为什么 `F.cross_entropy` 比手动 softmax + log 更好？
?
1. **数值稳定**：内部用 log-sum-exp trick 避免 exp 溢出
2. **内存高效**：不需要存中间的 counts 和 probs 张量
3. **代码简洁**：一行代替三行
<!--SR:!2026-04-14,8,250-->


随机猜测的基线损失 `-log(1/27) ≈ 3.30` 是怎么来的？
?
如果模型对 27 个字符完全均匀猜测，每个字符概率 = 1/27。
交叉熵 = -log(1/27) = log(27) ≈ 3.30。
任何有效模型的损失都应该低于这个值，否则还不如随机猜
<!--SR:!2026-04-08,2,230-->


Mini-batch SGD 相比全量梯度下降（full-batch GD）有什么优势？
?
- **更快**：每次只用 32 个样本计算梯度，不用遍历全部 22 万样本
- **噪声有益**：梯度的随机性帮助逃离局部最小值
- **内存友好**：不需要一次加载所有数据
- 代价是梯度方向有噪声，但平均方向仍然正确
<!--SR:!2026-04-13,7,250-->


训练循环中 `p.grad = None` 的作用是什么？和 `zero_()` 有什么区别？
?
两者都是清零梯度，防止梯度累积。
`p.grad = None` 比 `p.grad.zero_()` 更高效：后者在已有的张量上填零，前者直接释放内存，让下次 backward 创建新的梯度张量
<!--SR:!2026-04-08,2,230-->


学习率扫描（learning rate sweep）怎么做？为什么用对数刻度？
?
```python
lre = torch.linspace(-3, 0, 1000)  # 对数空间：-3 到 0
lrs = 10**lre                       # 实际 lr：0.001 到 1.0
```
用对数刻度是因为学习率的有效范围跨几个数量级（0.001~1），线性刻度会把小值全挤在一起看不清
<!--SR:!2026-04-08,2,230-->


学习率太高和太低分别会怎样？最优区间大约是多少？
?
- **太低**（如 0.001）：loss 下降极慢，收敛困难
- **太高**（如 0.5+）：loss 震荡甚至爆炸，梯度更新过猛
- **最优区间**：约 0.05~0.2，loss 稳定快速下降
实践中常先用大 lr 快速下降，后期衰减 lr 精细调整
<!--SR:!2026-04-08,2,230-->


为什么需要 train / val / test 三个数据集？各自的作用？
?
- **Train（80%）**：训练模型参数
- **Val（10%）**：调超参数（如 lr、hidden size），检测过拟合
- **Test（10%）**：最终评估，只用一次，模拟"没见过的数据"
如果只用 train + test，调超参数时 test 会被"偷看"，评估不公平
<!--SR:!2026-04-15,9,250-->


如何判断模型是否过拟合？本讲的例子中过拟合严重吗？
?
对比 train loss 和 val loss：
- train ≈ 2.09，val ≈ 2.14，差距很小 → 欠拟合（underfitting）居多
- 如果 train loss 远低于 val loss → 过拟合
本讲模型只有 11897 个参数，容量不大，所以主要瓶颈是模型太小而非过拟合
<!--SR:!2026-04-14,8,250-->


从 2D 嵌入升级到 10D 嵌入后，模型参数从 3481 变成 11897，怎么算？
?
| 参数 | 小模型 (emb=2) | 大模型 (emb=10) |
|------|------|------|
| C | 27×2=54 | 27×10=270 |
| W1 | 6×100=600 | 30×200=6000 |
| b1 | 100 | 200 |
| W2 | 100×27=2700 | 200×27=5400 |
| b2 | 27 | 27 |
| **总计** | **3481** | **11897** |
注意 W1 输入维度 = block_size × emb_dim
<!--SR:!2026-04-13,7,250-->


采样（生成）新名字的完整流程是什么？
?
1. 初始化 context = `[0,0,0]`（即 `...`）
2. 循环：context → 嵌入 → 隐藏层 → logits → softmax → 概率分布
3. 从概率分布中 `multinomial` 采样一个字符
4. 将新字符加入 context（滑动窗口右移）
5. 如果采样到 `.`（index=0），结束生成
<!--SR:!2026-04-08,2,230-->


`torch.multinomial` 和 `argmax` 采样有什么区别？为什么生成时用 multinomial？
?
- `argmax`：总是选概率最高的字符 → 确定性输出，每次生成同样的名字
- `multinomial`：按概率随机采样 → 有多样性，能生成不同的名字
语言生成需要多样性，所以用 multinomial；而分类任务通常用 argmax
<!--SR:!2026-04-08,2,230-->


Embedding 可视化（2D scatter plot）能看出什么？
?
将每个字符的 2D 嵌入画在平面上，可以看到：
- 相似功能的字符聚在一起（如元音 a/e/i/o/u 可能靠近）
- 距离远的字符在语言模型中行为差异大
- 这说明模型自动学到了字符间的语义/语法关系，无需人工设计特征
<!--SR:!2026-04-15,9,250-->


`stoi` 和 `itos` 分别是什么？为什么 `.` 的索引是 0？
?
- `stoi`：string to index，字符→整数映射（a=1, b=2, ..., z=26, .=0）
- `itos`：index to string，整数→字符映射（反向）
`.` 放在 0 是因为它代表"无字符/边界"，在初始化 context 时用 `[0,0,0]` 最自然
<!--SR:!2026-04-14,8,250-->


MLP 语言模型相比 bigram 模型的核心改进是什么？
?
1. **更长的上下文**：bigram 只看 1 个字符，MLP 看 block_size 个字符
2. **学习的嵌入**：字符不再是 one-hot，而是可学习的低维向量，能捕捉字符间关系
3. **非线性变换**：隐藏层 + tanh 让模型能学习复杂的条件概率分布
效果：loss 从 bigram 的 ~2.45 降到 MLP 的 ~2.09
<!--SR:!2026-04-13,7,250-->
